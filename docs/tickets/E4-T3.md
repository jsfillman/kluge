# E4-T3 Runtime compatibility

- Status: open
- Epic: [E4](epics/E4.md)
- Depends: E4-T2, E11-T2
- Spec: [cluster.md](../spec/cluster.md) "Runtime compatibility" and [language.md](../spec/language.md) "`#SBATCH`"

## Outcome

`render_workload` gains the compatibility pod, and the sbatch reader accepts the extra headers from the spec:

- a memory `emptyDir` mounted at `/dev/shm`, half the memory limit, or 8Gi when memory was unset and the limit is then 16Gi
- CPU and memory `limits` matching the requests
- stdout and stderr file paths, with `%j`, `%x`, and `%n` expanded in the rendered env
- `SLURM_JOB_ID`, `SLURM_JOB_NAME`, `SLURM_NNODES`, `SLURM_NODEID`, `SLURM_PROCID`, `SLURM_NTASKS`, `SLURM_CPUS_PER_TASK`, `SLURM_GPUS_ON_NODE`, `SLURM_SUBMIT_DIR`, `RANK`, `WORLD_SIZE`, `LOCAL_RANK`, `MASTER_ADDR`, and `MASTER_PORT` present in the container env
- a script run whose command is `bash --noprofile --norc /kluge/script`, and a one-line run whose command is still argv
- `--chdir` maps to `dir`
- `--export=ALL` is `parse.sbatch` and the message says the container starts clean

## Out of scope

The waiting-pod `srun` helper, the signal wrapper, and requesting an RDMA device. Those stay specified and unbuilt.

## Green

The renderer and the reader. No cluster.
